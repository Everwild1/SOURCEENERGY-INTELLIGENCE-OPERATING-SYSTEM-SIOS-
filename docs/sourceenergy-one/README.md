# SourceEnergy One

SourceEnergy One is the unified human experience layer for the SourceEnergy ecosystem. It is device-independent and delegates governed intelligence/orchestration to SourceCube while SIOS provides institutional execution infrastructure.

## Canonical operating chain

Human / Device -> SourceEnergy One -> SourceCube -> Governance Gates -> SIOS / Domain Services -> External Execution -> Audit

## Genesis experience

Purpose Discovery -> Codex 24 interpretation -> Mission, Vision, Purpose (MVP) + 100-Year Impact Report -> Human Review and Approval -> SETC Genesis -> SourceCube -> Wealth Ecology Journey

## Architectural boundaries

- SourceEnergy One: experience and interaction layer.
- Purpose Discovery: human-origin intake and testimony.
- Codex 24: emerging interpretation service; outputs remain candidate interpretations until human confirmation.
- SETC Genesis: approved provenance and starting-state boundary.
- SourceCube: internal intelligence and orchestration mechanism.
- Governance Gates: policy, authority, consent, risk and human authorization controls.
- SIOS: APIs, identity, data, registries, workflows, institutional integrations and execution infrastructure.
- Supabase: authoritative operational data platform where designated by the SIOS architecture.

## Engineering principles

1. API-first and device-independent.
2. Human authorization for consequential actions.
3. Raw Purpose Discovery narratives remain protected; Genesis stores governed references/provenance rather than unnecessarily exposing sensitive narrative data.
4. AI interpretation is distinguishable from user testimony and approved institutional records.
5. All consequential orchestration is permission-aware and auditable.
6. Domain services remain decoupled from the presentation layer.
7. SourceCube is not a customer dashboard; it is the orchestration mechanism beneath SourceEnergy One.
